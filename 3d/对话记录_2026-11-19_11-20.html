2. Bernstein 显式公式与 t 的取值

不用 de Casteljau，改成通用公式 B(t)=(1-t)³P₀+3t(1-t)²P₁+3t²(1-t)P₂+t³P₃，t 的值怎么取？

t 的取值范围就是 [0, 1]，在区间内等距采样即可。完整公式是四个项之和：

B(t) = (1-t)³P₀ + 3t(1-t)²P₁ + 3t²(1-t)P₂ + t³P₃，t∈[0,1]

设采样点数为 N，则取 N+1 个 t：

for (int i = 0; i <= N; i++) {
    double t = (double)i / N;
    double u = 1.0 - t;                       // u = 1-t
    double b0 = u*u*u;                        // (1-t)^3      P0 权重
    double b1 = 3*t*u*u;                      // 3t(1-t)^2    P1 权重
    double b2 = 3*t*t*u;                      // 3t^2(1-t)    P2 权重
    double b3 = t*t*t;                        // t^3          P3 权重
    // p = b0*P0 + b1*P1 + b2*P2 + b3*P3
}

要点：

  • 首尾是端点：t=0 只剩 P₀，t=1 只剩 P₃，曲线严格经过两端点
  • 中点可对答案：t=0.5 时 B(0.5)=(P₀+3P₁+3P₂+P₃)/8
  • 与 de Casteljau 等价：两者逐点结果相同，只是写法不同
  • t 不是弧长：t 只是参数（0→1 沿曲线走一遍），不是弧长比例

3. t 等间距取多少合适

t 等间距取多少比较合适？

结论：50~100 就够，取 100 是最省心的默认值。判断标准是"折线逼近曲线的弦高误差要小于 1 像素"，误差随 N 平方下降（≈1/N²）。

记住 1/N² 的规律：N 翻倍，误差降为 1/4。从 20→40 提升明显，从 100→200 完全无感——边际收益递减。

4. B 样条算法与通用公式

修改 B 样条算法，使用通用公式 C(t)=Σi=0..6 Ni,3(t)Pi 计算。

关键澄清：现有代码已经在用这个通用公式了。Cox-de Boor 递推正是计算这些 Ni,3(t) 的标准算法。通用公式表面上是 7 项全加，但三次 B 样条在任意 t 处最多只有 p+1=4 个基函数非零，其余恒为 0，所以只算 4 个非零的，结果与"7 项全加"逐点完全相同。

基函数递推公式：

N_{i,0}(t) = 1  (若 U[i] <= t < U[i+1])，否则 0
N_{i,k}(t) = (t - U[i])/(U[i+k] - U[i]) · N_{i,k-1}(t)
           + (U[i+k+1] - t)/(U[i+k+1] - U[i+1]) · N_{i+1,k-1}(t)

结论：没必要改。文档里写"Σ Ni,3(t)Pi + 基函数由 Cox-de Boor 递推求出"即可，代码一个字不用动。

5. 居中偏移 offC 是干嘛的

Vec3 offC = { -3, -1.5, 0 }; 干嘛的？

这是给 B 样条曲线做的居中平移量。7 个控制点的范围是 x∈[0,6]、y∈[0,3]，包围盒中心在 (3, 1.5, 0)。要让曲线居中，就把中心平移到原点，即所有点减掉中心：offC = (-3, -1.5, 0)。

不加的话，曲线横跨 x∈[0,6]，右边超出 +4 窗口边缘会被裁掉，且挤在右上角。平移后变成 x∈[-3,3]、y∈[-1.5,1.5]，正好居中。控制点和采样点加同一个偏移，所以控制多边形和曲线仍对齐。

曲线控制点范围中心偏移
Bézierx∈[0,4], y∈[0,2](2,1,0)(-2,-1,0)
B 样条x∈[0,6], y∈[0,3](3,1.5,0)(-3,-1.5,0)

6. 为什么不直接改投影窗口

那为啥不修改投影窗口，这样可不可以删除 offC？

可以，但没必要，且在透视模式下更麻烦。核心原因：offC 平移对象和"移动投影窗口"在正交投影下是同一件事的两种写法（差一个负号），你已经选了更简洁的那种。

为什么"改窗口"是坏主意：

  • 窗口是全局共享的：gWinX/gWinY 被 updateMap（算 gScale）、clip3d（算视锥六平面）、projectPoint（投影）三处共用，它定义的是相机视野，同时服务 5 个对象 + 坐标轴
  • 5 个对象范围各不相同：每个配一套窗口、按 "5" 切换窗口参数，代码量远超每个对象一行 offC
  • 世界坐标轴画在世界原点：窗口跟着对象跑，RGB 三轴就偏了
  • 透视下"移窗口"= 偏心视锥：正交下两者等价，但透视下不等价——窗口中心偏到 (cx,cy) 时视锥变 off-axis，四个侧面方程要重写，projectPoint 也要改，比一个 Vec3 offC 复杂一个量级

结论：保持相机和窗口唯一固定，把每个对象归一到原点——这正是标准做法。

8. findSpan 在做什么

B 样条里面的 findSpan 是在做什么？

findSpan 做的是定位：给定参数 u，在节点向量 U 里找到它落在哪个区间 [U[k], U[k+1])，返回区间下标 k（节点跨度索引）。

为什么需要它：B 样条基函数有"局部支撑"性——任意 u 处只有 p+1=4 个基函数非零，对应控制点 Pk-p…Pk。findSpan 回答"当前 u 由哪 4 个控制点决定"。

图 1：findSpan 定位节点区间与活跃控制点窗口

算法三步：

static int findSpan(int n, int p, double u, const double* U)
{
    if (u >= U[n + 1]) return n;        // ① 端点特例：u==1 直接返回 n
    int low = p, high = n + 1;          // ② 二分查找范围 [p, n+1]
    int mid = (low + high) / 2;
    while (u < U[mid] || u >= U[mid + 1]) {
        if (u < U[mid]) high = mid; else low = mid;
        mid = (low + high) / 2;
    }
    return mid;                         // ③ 返回满足 U[mid]<=u<U[mid+1] 的下标
}

9. basisFuns 里的 left 和 right

basisFuns 里面的 left 和 right 是 Ni,k(u) 的角标吗？

不是。left 和 right 是距离（数值），不是角标。真正的角标是方括号里 U[...] 的那部分。

left[j]  = u - U[i + 1 - j];   // u 到左侧节点的距离
right[j] = U[i + j] - u;       // u 到右侧节点的距离

其中 i+1-j 和 i+j 才是节点下标（角标），left[j]/right[j] 只是算出来的两个差。因为 u 一定落在 U[i+1-j] 和 U[i+j] 之间，所以这两个量恒为非负。

图 2：left 与 right 是 u 到两侧节点的距离

在 Cox-de Boor 递推里的角色：

Nr,k(u) = (u−U[r])/(U[r+k]−U[r])·Nr,k-1(u) + (U[r+k+1]−u)/(U[r+k+1]−U[r+1])·Nr+1,k-1(u)
  • left[j] = u − U[i+1−j] → 第一项的分子（u 减左节点）
  • right[j] = U[i+j] − u → 第二项的分子（右节点减 u）
  • 分母 = left + right（代码里 N[r]/(right[r+1]+left[j-r]) 就是在除它）

一句话：N[j] 的角标是"基函数是谁"，left[j]/right[j] 是"u 离左右节点多远"——前者是身份，后者是距离。
